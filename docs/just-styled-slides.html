The cost, part 2: work on every render

The style pipeline is JavaScript that runs while React is trying to paint your frame
hash
Class name generation
Resolve every interpolation, build the CSS string, MurmurHash it — per element, per render, before caching helps.
css
Style parsing
Each new style variant runs a full stylis compile: parse, nest, prefix, serialize — ~1.3 µs each.
props
Context + prop filtering
Merge props/theme/attrs into an execution context; filter every prop through DOM-validity checks.
fiber
Extra reconciliation
The wrapper fibers themselves: diffed on every parent re-render, hooks and context reads included.
A styled-heavy screen re-rendering at 60fps runs this pipeline ~72,000× per second (1,200 styled elements × 60 renders) — none of it wrong, all of it at the most expensive possible time.

Three-stage optimization

Move every piece of styling work to the earliest moment it can possibly happen
1
Build time
Compile styled templates to descriptors; provably-static CSS ships finished in the bundle.
33% need zero runtime style work
2
Module load + idle
Flatten static parts once; decide cascade order; compile remaining static CSS during browser idle.
never blocks a frame
3
Render time
JSX runtime swaps descriptors for host elements. Static = one compare. Dynamic = cached class.
no wrapper fiber, minimal work
1

Build time — compile the styling away

what the oxc engine does to this file, in ~1 ms
oxc engine
Rust parser + surgical string edits, ≈1 ms per styled file. Babel engine as reference and automatic per-file fallback.
1,326 of 4,044
of our styled components ship as finished CSS — zero runtime style work. Resolves theme constants, ${Component} selectors, css`` fragments, .attrs / .withConfig chains.
Differential-tested
Both engines produce equivalent output on all 1,244 styled files; unknown patterns safely stay on styled-components.
2

Module load + idle — prepare once, off the critical path

Flatten once
At definition, static template parts (module values, fragments, selectors) are baked into strings — only prop functions survive to render time.
once per component, not per render
Cascade decided up front
Every component takes a definition-order group; the stylesheet keeps groups ordered — a base always precedes its extender, with no render-time ordering logic.
styled(Button) beats Button, always
Idle compilation
Static components the build couldn't prove compile during requestIdleCallback — the browser's spare time — so first render just inserts a ready-made rule.
never blocks a frame

Render time — almost nothing left to do

Static component
one property compare
Rule already exists under its componentId. The JSX runtime emits the host element with that class. That's the whole render path.
Dynamic component
cache hit = map lookup
Interpolations resolve against props; the result maps to a per-component cached class. Only a never-seen variant pays for an insert.
New dynamic variant
flat CSS skips stylis
Plain declaration bodies become a rule by string concat instead of a stylis compile:
stylis compile1,345 ns
flat fast path206 ns
And in every case: no wrapper fiber was created, diffed, or reconciled.
