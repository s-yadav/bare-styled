just-styled reimplements the styled-components authoring model but resolves every styled component to a plain host element at JSX time, and compiles fully-static templates to finished CSS at build time. Benchmarked against real styled-components on identical source, it wins all nine measured profiles.

01The core idea

Every styled-components element is two React fibers: a wrapper component (which runs hooks, reads theme context, computes styles) and the host element. On a 150-row data table that's ~1,200 extra fibers created on mount and reconciled on every render. just-styled removes them entirely — the styled component is resolved before React ever sees it.

Decision that makes it safe: styling itself deliberately copies styled-components — resolve interpolations against props → hash → one class per distinct style, one rule inserted once. Output CSS and cascade semantics are equivalent by construction; the performance comes from structure (fewer fibers, work moved to build/idle time), not from a riskier styling model.

02Architecture decisions behind the numbers

Four decisions carry most of the win, plus a set of smaller optimizations that add up.

Fiber elimination mount +21–28%

Descriptors are resolved in a wrapped automatic JSX runtime (jsxImportSource: 'just-styled') — deterministic, no monkeypatching. Non-styled elements pay a single type check. The mount gain is flat across every profile and scale because it is purely structural: it's the wrapper fibers that are gone.

Static work moved off the render path re-render +43–53% (static rows)

Templates provably static at build time ship as finished CSS in the bundle — zero runtime style work. Static-but-unprovable templates compile during requestIdleCallback. At render, a static element costs one property compare; styled-components still runs its full wrapper + style pipeline per element.

Aggressive build-time resolution 33% of prophecy fully precompiled

The precompiler resolves more than literals: module-const member chains (${theme.border}), same-file ${Component} selectors (the componentId was just minted by the same pass), and same-file static css`` fragments — inlined recursively. .attrs(...) / .withConfig(...) chains compile natively too (attrs expressions stay live; styled-components semantics at render). Across prophecy's full corpus: 4,044 components compiled, 1,326 shipped as finished CSS, all 58 attrs chains included.

Stylis skipped for flat dynamic bodies 6.5× cheaper per new variant

A resolved body with no nesting / at-rules is already a valid rule: .cls{body} by string concat (206 ns) instead of a stylis compile (1,345 ns). Value-position interpolations — the common high-cardinality shape — all qualify. This flipped high-cardinality from the narrowest profile to the widest (+59–64% re-render).

Other minor improvements

  • Faster sheet ordering logic — rule-position math on the stylesheet is O(log n) instead of a linear walk, so cold mounts with thousands of components insert rules cheaply.
  • More caching — resolved styles cache per component, compiled static rules cache by componentId, keyframes by name; unchanged styles never recompute anything.
  • Hot-path optimizations — fixed-arity JSX wrappers (no arguments/apply deopt), a single cheap type check for every non-styled element, generation stamps instead of set lookups on the static path.
  • No object mutation after creation — props objects are built once with copy-skip loops instead of delete, keeping V8 hidden classes stable on the per-element path.

05Reading the results

Mount is flat at ~19–29% — by design

The mount gain barely moves between 508 and 2,228 nodes or between static and dynamic mixes. That is the signature of the structural win: the wrapper fibers are gone, and that saving scales linearly with tree size. It does not erode at real-page scale.

Re-render is where decisions compound

Static-heavy rows approach +51% (one property compare per element vs a full wrapper render), and high-cardinality dynamic hits +54% (every new style variant skips stylis). The narrowest case, all-dynamic low-cardinality (+37%), is intentional: per-render resolution matches styled-components' own algorithm, so the remaining edge there is purely the fiber.

What jsdom can't show — the numbers are conservative

jsdom measures JS/React cost only. Browser-side effects — CSSOM rule insertion and style recalc — are on top of these numbers. The browser harnesses (profiling/*/harness.html) measure those with a full style+layout flush per render.

The transform itself is cheap too

Two build-time engines produce equivalent output (differential-tested on prophecy's full corpus: 1,244 styled files, zero errors). The default oxc engine (oxc-parser + magic-string surgical edits) transforms at ≈0.7–1.5 ms/file vs Babel's ≈5.4–5.8 — 3.6–8.5× depending on filesystem — so the styled pass adds under two seconds to a cold build of the whole app. Reproduce with node profiling/transform-bench.mjs.

06Methodology & caveats

Identical source compiled two ways; identical DOM verified by node count each run. Median over 12–25 iterations after 3 warmup mounts, flushSync rendering, production React. Run-to-run jsdom noise is roughly ±4 points — differences under that are directional. Components using .attrs/.withConfig or context theme intentionally fall back to real styled-components in both harnesses, exactly as they do in production.
